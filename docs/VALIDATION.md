# 可信度与已知局限

本文件说明 tdlas-mcp 输出**哪些部分可信、可信到什么程度**，以及自动校验（`tdlas_review` /
`validation`）各判据的口径与使用边界。目的是避免两类误用：把仿真值当实测值、把"提醒"当"结论被否"。

> ⚠️ 本工具输出的是**理论仿真**，不是实验测量。论文中使用须按 README 的引用格式标注"理论仿真"。

---

## 1. 分层可信度

| 层面 | 可信度 | 判据 |
|------|--------|------|
| 取数层（HITRAN/HAPI） | **高** | 直接取自 HITRAN2024 线表，与独立实现的相对偏差在 0.4% 量级 |
| 物理建模（Beer-Lambert / Voigt / WMS） | **高** | 与解析模型互为独立路径，形状相关 0.9848；DAS 链路闭环 1.0% |
| 自检机制（`tdlas_selftest`） | **中** | 10 项全过，但多数为"自洽检验"（见 §2），仅 1 项是真正的独立互校 |
| 自动校验（`validation`，10 判据） | **中** | 硬判据（采样率 / ADC 动态范围 / 归一化方法 / etalon 混叠）可直接照做；形态类判据须按谱线密度打折（见 §4） |
| AI 交互协议（`tdlas_guide` / 参数索取） | 设计特性 | 强制澄清、参数四级优先级、设备库，属工程规范而非物理结论 |

**结论**：数值可作方法验证与系统选型的依据，**不可**替代实测。

---

## 2. 自检（`tdlas_selftest`）怎么看

`tdlas_selftest` 的 10 项里，**只有"时域锁相 vs 解析模型"是真独立互校**（两条不同算法路径互证）；
其余 9 项是"自己验自己"——能证明链路无代码 bug、无量纲错误，**不能证明物理建模与真实世界一致**。

| 项目 | 性质 |
|------|------|
| 取数 / 吸收谱（α 峰值非零） | 自洽（线表可读、无空谱静默） |
| 2f 中心峰位置（不贴扫描边界） | 自洽（扫描窗口够宽） |
| 弱场线性度 | 自洽（理想链路应线性） |
| 反演闭环 | 自洽（正演→反演回原值） |
| 检测限（NEC / LOD 量级） | 自洽（蒙特卡洛） |
| 时域锁相 vs 解析模型（2f 形状相关） | ✅ **独立互校**（两套算法） |
| DAS 链路（孤立线基线拟合） | 自洽（对照解析 αL） |
| 电压自适应（amp_V/offset_V 反算） | 自洽（对照 V→ν 解析解） |
| 越界保护（wn_center 超调谐范围） | 自洽（异常路径） |
| 二次调谐可达性（判别式 < 0 必报错） | 自洽（异常路径，见 §6） |

**正确用法**：自检通过 = "实现自洽"；要判断物理正确性，须做**外部交叉验证**（§3）。

## 3. 外部交叉验证示例

对同一波数窗口，用独立脚本按 HITRAN 线表手算 `αL`，与 MCP 返回的 `alpha_L_peak` 对比：

```
同一窗口（CH4，2963.2–2966.2 cm⁻¹）：
  MCP   key_metrics.alpha_L_peak = 2.3755e-3
  独立脚本 α_pure·x·L            = 2.366e-3
  相对偏差                        = 0.4%
```

这正是验证取数层与 DAS 反演链路的推荐做法。

## 4. 自动校验（10 条判据）口径

| 判据 | 类型 | 口径与注意 |
|------|------|-----------|
| 波数轴对齐 | 硬 | 扫描窗口须覆盖 `wn_center` |
| 采样率 | **硬** | 每调制周期 ≥8 点；不满足时链路会自动吸附到合法整数倍并回写 |
| ADC 动态范围 | **硬** | 有饱和点即 fail，须降增益 / 加大量程；信号 ≪ 量程记 warn（浪费动态范围） |
| 归一化方法 | **硬** | 未背景扣除时记 warn；`2f/1f` 失效会自动退化为 `2f/I0` |
| 弱吸收区 αL | 硬 | `αL ∈ [1e-5, 0.1]` 为线性区；>0.1 进入非线性，2f 将偏离线性 |
| 调制系数 m | 提醒 | 自适应模式下按谱线密度选优（孤立≈2.2 / 中等≈1.8 / 密集≈1.25），一般不报警 |
| DAS-理论一致 | **形态** | 见下方"口径说明"；多线窗口的大偏差不作硬 fail |
| 孤立单线 | **形态** | 窗口内 >10 条线即提醒：2f 是多线叠加，非标准双峰，DAS 包络更直观 |
| 噪声 | 告知 | 默认理想无噪，须在结论中向用户说明 |
| etalon 条纹 | **硬（混叠）/ 形态** | 默认关；启用后 `step > FSR/10` 判 **fail**（条纹混叠）；`线宽 ≤ FSR ≤ 10×线宽` 判 **warn**（会与 2f 吸收混淆） |

`overall = fail/warn/pass`：任一 fail → fail；否则任一 warn → warn。
**fail 时不得下结论**，先修 fail 项；warn 项须在结论中说明。

### 口径说明：`DAS-理论一致` 的两个峰值不是同一个数

- **本判据**比较的是**有效区**（已按 `trim_frac`，默认剔除扫描两端各 12%）内 DAS 与理论 αL 的峰值；
- **`key_metrics.alpha_L_peak`** 报告的是**全窗（未剔除）**理论峰。

若窗口内最强线恰好落在被剔除的两端，二者可差约 2×——**这是正常现象，不是自相矛盾**。
判据详情会在差异 >20% 时同时列出全窗峰并注明口径，避免误读。

## 5. 使用口径

1. **10 条判据里三档硬判据照做**：采样率、ADC 动态范围、归一化方法。
2. **`孤立单线` 是形态提醒**：密集谱区 2f 必然多峰，这不代表出错。
3. **`DAS-理论一致` 按谱线密度打折**：多线窗口只作提醒，请以 DAS 包络 / 2f 多峰形态判断。
4. **要复核就带真实硬件重跑**：`tdlas_review` 与 `tdlas_wms_instrument` 同源，支持同样的硬件参数
   （`v_range` / `adc_bits` / `gain` / … 或 `setup=` / `daq=` 等设备引用）。**务必传入真实硬件**，
   否则默认量程可能与实际信号不匹配而出现 ADC 饱和，使 `overall` 误报 fail。
5. **数值可信到 0.4% 量级**，但它是**理论仿真值**，不等于实测值。

## 6. 已知局限

| 陷阱 | 症状 | 正确做法 |
|------|------|---------|
| 默认量程与实际信号不匹配 | `validation` 报 ADC 饱和 fail | 传 `v_range` / `gain`，或用 `daq=<设备名>` 引用设备库；不要只凭默认量程的 overall 否定结论 |
| 密集谱区用标量峰值比判断 | `DAS-理论一致` 出现大偏差 | 多线窗口该判据只作提醒，改看 DAS 包络与 2f 多峰形态 |
| 误把有效区峰与全窗峰对读 | 两个 αL 数值差约 2× | 二者口径不同；`key_metrics.alpha_L_peak` 是全窗值 |
| 弱吸收 + 16-bit ADC | 吸光度仅约 1.5 LSB，"DAS-理论一致"难以优于 2% | 提高光程 / 浓度或换更高位数 ADC |
| `2f/1f` 无背景扣除 | 超线性、偏离标定 | 保持 `background_subtract=True`；1f 过零是物理奇点，非失效 |
| 越界工况 | 抛 `ValueError`（offset_V 超 0–5 V） | `wn_center` 须落在该激光器调谐范围内，或提供对应 `wn_ref` / `dν/dI` / `η_VI` |
| 二次调谐目标波数不可达 | 抛 `ValueError`（判别式 < 0，附提示可达极值） | 核对 `wn_ref` / `dν/dI` 数值与符号、`d²ν/dI²` 是否合理；该波数本应可达时置 `d2nu_dI2=0` 改用线性模型（**不会**再伪造出一个驱动电压） |
| 峰值与灵敏度不同区间 | 反演浓度明显离谱 | `results.S2f1f_peak` 与 `results.sensitivity_k` 同在**有效区**取峰，可用 `S2f1f_peak_interval` 核对是否落进剔除区 |
| 反演结果越界 | 摩尔分数 > 1（或为 0） | 结果**不静默截断**：读 `mole_frac_status` / `mole_frac_valid` / `warning`；越界即说明 k 与工况不同源或已出弱吸收线性区 |
| 设备参数非法 | 仿真出 nan、负带宽、非法 ADC 配置 | `tdlas_device save` 与设备引用**双向校验**并报错；保存时返回 `ignored_params` 提示拼错的键 |
| 按推荐波段选线却报错 | `ValueError: offset_V 越出驱动器 0–5 V` | 默认激光受阈值电流约束，实际只覆盖 **2964.7–2972.6 cm⁻¹**；`adaptive_condition` 的「波段可达性」会给出该波段需要的 `wn_ref`。`auto_laser=True`（默认）会自动重锚 |
| 以为用了自己的激光器 | 结果与实测对不上 | 当返回里 `laser_auto_aligned` 非空时，`wn_ref` 是**自动重锚的理想假设**（不是你手上的器件）——必须用实测 `wn_ref`/`dν/dI` 覆盖，或用 `tdlas_device` 保存真实激光器后 `laser=` 引用 |
| 两次同参调用结果不同（旧版） | 论文里写的数别人复现不了 | 已修：`seed` 默认 **0** ⇒ 默认逐位可复现；返回带 `seed_used`。要随机性传 `seed=null` |
| 以为"理想仿真 = 没噪声" | 把散粒/热当成可关闭项 | 散粒/热是**物理固有、恒在**（默认 ~0.03 mV）；RIN/1f 才是可关项。要完全无噪用 `physical_noise=False` |
| 一次 502 被读成"该波段没收录" | 据此换波段、甚至断言"该气体无吸收" | 取数失败已**自动重试 3 次**并用离线索引区分服务端故障与"同位素确实不存在"；报错文案会明确写"这是网络/服务端故障，不代表无谱线" |
| etalon 条纹当噪声处理 | 以为降噪 / 多次平均能消除条纹 | 固定腔长的条纹是**确定性项**，只能物理解决（窗片楔化 / AR 镀膜 / 扫频）；并保证 `step ≤ FSR/10`，否则条纹混叠 |

## 7. 修订记录

- **2026-09-14**
  - 默认跨阻增益 `1e3 → 700`：旧默认使默认工况 `v_pd≈10.9 V` 超出 ±10 V 量程 → ADC 默认即饱和、
    `tdlas_review` 默认必 fail；现默认工况 `v_pd≈7.7 V`。
  - `tdlas_review` 的 `inputSchema` 补齐硬件 / 设备参数（此前实现可透传但未声明，AI 客户端无从传入）。
  - `DAS-理论一致` 判据：明确"有效区 vs 全窗"口径；多线窗口大偏差不再硬 fail；pass/warn 两档不受谱线密度影响。
  - 新增 **etalon 干涉条纹模型**（默认关）：光路 Airy 透过率 `T = 1/(1 + F·sin²(δ/2))`、`FSR = 1/(2nd)`；新增校验第 10 项（`step > FSR/10` 判混叠 fail；FSR 为线宽数倍判 warn）；新增自适应 `fringe_report`。自动校验 9 → 10 项。

- **2026-09-16（代码审计修复，4 项 + 2 项工程加固）**
  - **`results.S2f1f_peak` 与 `sensitivity_k` 统一到有效区取峰**：此前 `S2f1f_peak` 用**全窗** `argmax`，被 `trim_frac` 剔除的边缘点（三角波转折处伪影）可能被当成"峰值"，导致这对**本应配套**的数不自洽、直接送 `tdlas_invert` 会算错浓度。现改在 `valid_mask` 内取峰，并新增 `S2f1f_peak_interval`（含 `full_window_peak_in_trimmed_edge` 诊断位）供核对。
  - **二次调谐判别式 < 0 改为硬报错**：此前 `max(disc, 0)` 把无实根情形截成"重根"，**伪造**出一个驱动电压让下游照常出谱；现抛 `ValueError` 并给出可达极值与该查的参数。
  - **`tdlas_invert` 输入/输出域校验**：`peak_2f1f` 须为有限值且 ≥0、`k` 须为有限正数（否则报错）；结果超出摩尔分数定义域 `(0,1]` 时**不静默截断**，改以 `mole_frac_status` / `mole_frac_valid` / `warning` 显式标注越界。
  - **设备库参数校验**：`tdlas_device save` 拒绝空设备名与非法参数（`gain/bw/fs/v_range/eta_*` > 0、`adc_bits` 为 4–32 整数、`throughput ∈ (0,1]`、`dnu_dI ≠ 0`）；**设备引用时再校验一次**，兜住历史/手改的非法条目；拼错的键回报在 `ignored_params`。
  - **缺依赖提示**：缺少 `hitran-api` 时给出可操作的安装指引（含当前解释器路径），`--selftest` 以非零码退出。
  - 自检新增第 10 项「二次调谐可达性」（不可达必报错 + 可达时取近根正常反算），自检项数 9 → 10。
